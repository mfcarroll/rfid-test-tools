Chameleon Ultra Hitag 2 emulation (experimental)

The CU emulates a Hitag 2 tag and answers a real reader's commands in time, the way a fob does. Set up a test tag here, hold the CU to a Hitag 2 reader, and read back the exchange: whether the reader read the UID, whether it uses password or crypto mode, and how it answered. It records what a reader does without needing a Proxmark3.

Everything happens in this browser. The page talks to the CU over USB. Nothing is sent to any server, and it saves nothing unless you press Copy or Download.

This is a made-up test tag, not a working credential. It uses a placeholder UID and password and opens no door. A reader reads the UID and then asks for a password; unless you know and set the reader's own password, the read stops there. That still proves the reader sees the tag and shows which mode it uses.

Keep the CU plugged into this computer while testing. The exchange trace is kept in memory and is lost when the CU sleeps or loses power. USB power keeps it awake, so hold the CU to the reader with the cable attached, then read the trace here.

Connect the Chameleon Ultra

This page requires Chrome or Edge on a computer. Use USB, not Bluetooth, and close anything else using the CU, such as the CU app or the Python CLI.

Checking the firmware…

This firmware has no interactive LF engine. Flash the experimental firmware below, then connect again.

1. Set up the test tag

Sets the active slot to Hitag 2, loads these values, and saves. A reader only needs the UID to start; set the password only if you know the reader's own.

2. Clear the trace, then test at the reader

Clear the trace, hold the CU to the Hitag 2 reader (cable still attached), then read the trace.

Firmware

The emulation needs the experimental firmware: the interactive LF engine with the Hitag 2 module (source). Flashing replaces the CU's firmware and keeps the current slots.

What the page does

        
    
          
  1. 
            Set up the test tag puts the active slot in Hitag 2 mode,
            loads the UID and password you enter (with a placeholder
            configuration and data pages), saves, and switches the CU to tag
            mode.
          
    2. 
          
  2. 
            At the reader, the CU listens for each command and answers in the
            reader's timing window. A reader sends START_AUTH to ask for the
            UID, then a 32-bit password (password mode) or a 64-bit command
            (crypto mode). The CU answers the UID, and, if the password matches
            the one you set, the configuration and data pages.
          
    3. 
          
  3. 
            Read the trace reads the record of the exchange and works
            out, in this browser, what the reader did: whether it read the UID,
            which mode it uses, and whether it authenticated.
          
    4. 
        

        

          The emulation answers password mode only. A crypto-mode reader
          reads the UID but goes no further, which the report names. The trace
          lives in memory, so keep the CU on USB power during a test. It has
          been checked against a Proxmark3 acting as a reader, not yet against
          door readers. The result is a guide, not a verdict.
