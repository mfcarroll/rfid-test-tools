Chameleon Ultra pulse test (experimental)

Some readers switch their field on for 50 to 80 ms at a time, over and over, and a frame from the CU has to fit inside one of those pulses. This test firmware puts the same HID Prox, Paradox or ioProx card in slots 1–7, each with a different way of answering such a reader. Try each slot at the reader and compare them.

Connect your Chameleon Ultra

Plug your CU in to USB, not Bluetooth, and close anything else using it, such as the CU app or the Python CLI. This page needs Chrome or Edge on a computer. It works with the Chameleon Ultra only, not the Lite.

Set up the slots

The page copies one HID Prox, Paradox or ioProx card into slots 1–7. The firmware fixes each slot's mode, listed below. Load the card into any slot first, with your usual app or by reading it here. A backup of every slot downloads before anything changes. Slot 8's LF card is removed and slot 8 is disabled, so the CU's buttons skip it. An HF card in slot 8 stays, disabled; a restore enables it again.

The slots and their modes
Slot Now Mode

Only the slots' LF side changes. An HF card in the same slot stays. Each slot gets an LF nickname naming its mode, e.g. "Paradox 5 pulse+x+learn".

Start testing clears the CU's earlier results and event log. The results then come from the next reader alone. Slots and modes stay as they are.

Test at a reader

  1. Unplug the CU and take it to the reader. Start on slot 1 and go in order to slot 7.
  2. On each slot, hold the CU to the reader for about 5 seconds, then take it away. Do that about 5 times per slot. Note how many times it opened, and roughly how long it took.
  3. Slots 4 and 5 measure the reader before they send the card. Their first try is the measurement, so note it separately. After that they keep what they measured.
  4. Test one reader at a time. Start testing again before another reader.

The CU keeps its results while it sleeps. Back here, connect again and read them.

About these columns

Fields seen: how many times the slot detected a reader's field arriving. Short fields: fields that were gone again within about 300 ms, as a pulsing reader's are. Trim: the reader's clock the slot matches, against the CU's. Slots 4 and 5 learn it from the reader; slots 6 and 7 use a fixed value.

Firmware

The test firmware is the self-trim test firmware (the Paradox pull request and the self-trim research) with the pulse test's slots added (source). Flashing keeps your slots and saved cards, and clears what the slots learned. Stock v2.3.0 has no Paradox support. When you're done, flash stock back, or use "Flash a file" for another application DFU package (a .zip).

What the slots do
  1. stock: works the same as stock firmware. The CU sends its card in bursts of 10 frames, about 0.4 s, and only then checks the reader's field.
  2. pulse timing: a card loses power between a reader's pulses and starts its frame again at each one. In this mode the CU does the same. It starts a fresh frame 2.1 ms into each field, as a T5577 does, sends a second frame straight after it, then checks the field. It does that for a field's first 3 pairs of frames. A field that stays on gets the usual 10-frame bursts after that.
  3. + exact bits: stock firmware sends some HID Prox and Paradox bits 4 % short, which makes the whole frame 2 % short. This mode makes every bit the standard length on average.
  4. + learned trim: the CU's clock and the reader's can differ. Over one frame that shifts the bits against the reader's own timing. This mode measures the reader's clock in its first pulses, without sending the card, then trims the card's timing to match. It needs two measurements that agree, and keeps the result.
  5. As 4, with exact bits.
  6. + fixed trim: as 5, but with a trim set in advance, from one Paradox reader that ran 0.52 % fast against the tester's CU. It tests the trim even if the learning fails.
  7. + drive: as 6, with the CU also driving its coil for a stronger signal. The drive only helps if the trim matches the reader; otherwise it drifts in and out of step.

Backup and restore

A backup is a file with every slot's LF side: card type, card data, whether it's enabled, its nickname and its mode. Restore puts every slot's LF side back. HF cards are never changed. The file contains your cards' data. Keep it somewhere private. The file lists card types this firmware can't read (Indala, for example), but the page can't restore those card types.

For developers
  • Command 3120 reports each slot's mode and the fields seen. Command 3130 reports what each slot learned from the reader's pulses and the short fields. 0xC1 to either clears the results.
  • Command 3100 at offset 0xFFFE reads the event log: the last 32 events, kept while the CU sleeps. Offset 0xFFFC clears it.
  • The page's parsing is in pulse.js. The card data only passes between the CU and the page's memory. The page never shows, logs, stores or sends it, except in a backup file you download.
