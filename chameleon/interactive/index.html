Chameleon Ultra interactive LF emulation Experimental

Emulate an interactive LF tag — one that answers a reader's commands, not just a fixed card number. The first one is Hitag 2 in password mode. Set up a test tag, take the CU to your reader, and the page tells you whether the reader engaged with it and how far the exchange got.

The tag's details are yours to set. The fields show a made-up tag in grey. Type your own, read a real tag, or fill the blanks with the example. A password you type or read stays on this page — it goes into the slot and the private details, never the safe report. The UID does appear in the safe report, since a reader broadcasts it over the air anyway.

This firmware has no interactive LF engine. Flash the experimental firmware below, then connect again.

1. Set up a Hitag 2 tag

Enter the tag's eight pages, read a real tag into the fields, or load a slot that already holds a Hitag 2 card. Then write it to a slot, which also makes that slot active. Each field is hex. For a reader to authenticate, the reader password (page 1) must match the one the reader sends. The config byte is fixed at 06 — Hitag 2, password mode, the only mode supported.

To test the timing modes, write the card to a slot here, then use the Hitag 2 modes page to copy it into every slot, each with its own mode.

#dataasciiInfo 0

Or read a real tag: hold it to the CU and read its UID, or, with the tag's password in page 1, read all its pages into the fields.

2. Clear the log, then go to the readers

            

              Clear the log, unplug the CU, and take it to the readers. The CU
              logs every presentation in its flash, which holds about two days
              of testing on every slot and keeps it through sleep and a flat
              battery. Read it back here afterwards. Each wake is a new boot in
              the report.
            

            

              Read the log out before you flash other firmware: a build with a
              different log format erases it.

What the page does

        
    
          
  1. 
            Makes the chosen slot active and sets it to a Hitag 2 tag with the
            UID, password, config and tag password you entered — or that it read
            from a real tag — and saves it.
          
    2. 
          
  2. 
            The CU's interactive engine listens for a reader's commands and
            answers them: it gives its UID to START_AUTH, and if a reader's
            password matches the stored one it serves the data pages.
          
    3. 
          
  3. 
            Each presentation and each command goes into a log. The CU keeps it
            in RAM while a reader's field is present and saves it to flash while
            none is, so it survives sleep and a power loss. Every wake from
            sleep is a new boot. Firmware before the log keeps only the first 8
            and the latest 40 records, in RAM.
          
    4. 
          
  4. 
            The safe report says whether the reader engaged and how far it got,
            by command length, never by content, with a table per slot and per
            mode. The private details hold the decoded bits, the reader's
            password among them.
