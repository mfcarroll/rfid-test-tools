Firmware

The test firmware is the interactive LF engine with per-slot Hitag 2 modes (source). Flashing keeps your slots and saved cards, and resets every slot's mode to baseline. Stock v2.3.0 has no Hitag 2 emulation. When you're done, flash stock back, or use "Flash a file" for another application DFU package (a .zip).

If the CU holds a log of reader tests, read it out on the Interactive LF emulation page before you flash. A build with a different log format erases it.

What the modes do

Each slot has three independent mode bits, so eight combinations, one per slot. Default setup gives each slot one of them, from slot 1 (baseline) to slot 8 (all three on). One walk past a reader then compares scale, every-second and rest-loaded, and their combinations.

  • scale: the CU measures the reader's carrier at the start of each field and times the answer's bits and delay in that reader's carrier periods. Without it, a carrier period is taken as 8 µs (125 kHz), so the answer drifts against a reader whose clock is off.
  • every-second: the tag answers only every second START_AUTH. The HT2 datasheet (rev 2.1, 4.2.2) says a second START_AUTH resets a genuine tag's state machine, so it answers only every second one. A reader that relies on that may reject a tag that answers every time.
  • rest-loaded: after each answer the CU listens with its load on at once, as older firmware always did. Without it the CU holds the load off for 56 carrier periods first, as a genuine tag rests unloaded, so the answer's last half-bit ends cleanly. A door reader has accepted rest-loaded, so it stays here for comparison.

The modes are kept in retained RAM. They survive sleep, so a test runs at a reader on battery, but reset to baseline on a power-on reset or a flash. Saving the slots does not save the modes.

Test at a reader
  1. Unplug the CU and take it to the reader. Start on the first slot.
  2. Hold the CU to the reader on each slot, several times. "scale" measures the reader at the start of each field, so its first read on a slot can be slower.
  3. Note for each slot whether it read, how quickly, and how close the CU had to be. The slot's nickname names its mode.
  4. Test one reader at a time. This page sets the modes; it reads no results back. To see what a reader actually sent, how the tag answered, and which mode each session ran in, open the Interactive LF emulation page and read the log. It works with this same firmware, with no reflash. It records each presentation's slot, mode and carrier, and gives a table per slot and per mode. On firmware with the flash log, one clear holds a day of testing on every slot.

Backup and restore

A backup is a file with every slot's LF side: card type, card data, whether it's enabled, its nickname and its mode. Restore puts every slot's LF side back. HF cards are never changed. The file contains your cards' data. Keep it somewhere private. The file lists card types this page can't read (anything other than Hitag 2), but can't restore those card types.

For developers
  • Command 3188 reads the eight slot modes (send nothing), or sets them (send eight bytes, one per slot, the LF_IA_MODE_ flags: 0x01 scale, 0x04 every-second, 0x08 rest-loaded). The firmware ignores 0x02, which older builds used for a later answer.
  • Copying a card reads the source slot's Hitag 2 data with command 5041 and writes it to each target with command 5040 (32 bytes, eight 4-byte pages).
  • The page's parsing is in hitag-modes.js. The card data only passes between the CU and the page's memory. The page never shows, logs, stores or sends it, except in a backup file you download.
